# 单话详细设计

将 story-structure 中的一行概要，展开为可执行的分镜蓝图。
这是从「故事设计」到「视觉执行」的关键桥梁。

---

## 前置检查

1. **必须存在**:
   - `comic-project/design/story/story-structure.md`（本话的剧情目标、伏笔计划等）
   - `comic-project/design/story/episode-index.md`（确认话数有效）
   - `comic-project/design/world/worldbook.md`（场景选择）
   - 本话涉及角色的 `comic-project/design/characters/*.md`
2. **建议存在**:
   - 前一话的 `ep{N-1}-design.md`（衔接）
   - 前一话 storyboard 的结束状态摘要（如存在，优先用于衔接）
   - `comic-project/concept/comic-concept.md`（可选参照）
3. **解析参数**: 提取话数 N。无参数则询问用户要设计第几话。

---

## Phase 1: 上下文加载

静默读取所有依赖文件，提取本话相关信息：

从 `story-structure.md` 提取：
- 本话的剧情目标、所属幕
- 本话的角色弧线推进任务
- 本话涉及的伏笔（埋设或回收）
- 本话的信息揭示计划
- 本话的主题论证阶段
- 本话的目标张力等级

从 `episode-index.md` 提取：
- 暂定标题、一句话概要

从前一话资料提取：
- 结束状态（优先取 storyboard 结束状态摘要，其次取 ep{N-1}-design 的计划结束状态）

向用户展示上下文摘要，确认无误后继续。

---

## Phase 2: 核心任务清单

将从 story-structure 提取的信息整理为本话必须完成的任务清单：

```
## 本话核心任务

### 主线任务（必须完成）
- ☐ {从 story-structure 主线弧线提取}

### 支线任务
- ☐ {从支线追踪提取，如有}

### 角色弧线推进
- ☐ {角色名}: {本话要推进什么}

### 伏笔任务
- ☐ {伏笔名}: {埋设/回收}
  | 伏笔名 | 操作 | 埋设时的伪装 | 回收话 | 回收时的真相 | 视觉呈现方式 |

### 信息揭示任务
- ☐ {信息}: {揭示方式}

### 主题论证任务
- ☐ 本话在主题论证中的角色: {阶段描述}
```

用 `AskUserQuestion` 确认任务清单，用户可增删调整。

---

## Phase 3: 页面预算

- **单话目标页数**: 继承自 `comic-concept.md`
- **本话实际分配页数**: 基于任务量评估
- **容差检查**: 实际页数是否在目标 ±2 页范围内
- 如超出容差：说明原因 + 调整方案

---

## Phase 4: 叙述策略

引导用户决定本话的叙述方式：

- **视角**: 跟谁？读者知道的比角色多还是少？
- **时间结构**: 线性 / 插叙 / 倒叙 / 平行
- **信息控制**: 本话读者应该知道什么、不应该知道什么
- **悬念管理**: 本话要解答的旧悬念 + 要抛出的新悬念

---

## Phase 5: 场景列表

按叙事顺序列出本话所有场景：

| 序号 | 场景名 | 地点 | 出场角色 | 场景目的 | 预估页数 |
|------|-------|------|---------|---------|---------|
| 1 | | | | | |
| 2 | | | | | |
| ... | | | | | |
| **合计** | | | | | **{N}页** |

- 页数合计行与页面预算交叉校验
- 如超出，引导用户调整（压缩某个场景或删减场景）

---

## Phase 6: 情绪地图

逐页规划情绪节奏：

| 页 | 目标情绪 | 张力(1-10) | 实现手段 |
|----|---------|-----------|---------|
| 1 | | | |
| 2 | | | |
| ... | | | |

绘制 ASCII 张力曲线图，检查：
- 是否符合 story-structure 中本话的目标张力等级
- 是否有合理的起伏（不是平直线）
- 高潮点的位置是否合理（通常在 2/3 处或接近结尾）

---

## Phase 7: 爽点/笑点/钩子设计

### 爽点设计
| 位置(页) | 类型 | 描述 | 视觉实现方式 |
|----------|------|------|------------|

### 笑点/轻松点设计
| 位置(页) | 类型 | 描述 | 注意事项 |
|----------|------|------|---------|

### 钩子设计
| 类型 | 位置 | 内容 | 目标效果 |
|------|------|------|---------|

- **话尾大钩子**（必须有）: 让读者想看下一话
- **中段微钩子**（可选）: 维持阅读动力
- **翻页钩子**: 利用日式左翻的翻页机制，在右页尾制造悬念

---

## Phase 8: 分镜执行备注

给 `/storyboard` skill 的约束指令：

- 特殊构图要求（如：某场景必须用鸟瞰视角）
- 特殊镜头要求（如：某对话场景必须保持固定机位）
- 伏笔的视觉呈现方式（从伏笔任务中提取）
- 翻页利用点（哪些页的翻页效果要特别设计）

---

## Phase 9: 确认与输出

1. 展示完整单话设计草稿
2. 用 `AskUserQuestion` 确认
3. 写入 `comic-project/design/story/ep{N}-design.md`

**文件结构**:

```markdown
# 第{N}话: {标题}

## 元信息
- 话数 / 所属幕
- 前一话结束状态
- 本话结束状态
- 下一话预期

## 页面预算
- 目标页数 / 实际页数 / 容差

## 核心任务清单
{Phase 2 内容}

## 叙述策略
{Phase 4 内容}

## 场景列表
{Phase 5 内容}

## 情绪地图
{Phase 6 内容，含 ASCII 曲线}

## 爽点设计
{Phase 7 爽点部分}

## 笑点/轻松点
{Phase 7 笑点部分}

## 钩子设计
{Phase 7 钩子部分}

## 分镜执行备注
{Phase 8 内容}
```

4. 更新 `episode-index.md` 中本话的状态为「✅ 已设计」
5. 更新 `production/session-state.md`

推荐下一步：
- 「运行 `/storyboard {N}` 开始本话的分镜脚本」
- 「运行 `/episode-design {N+1}` 设计下一话」
- 「运行 `/gate-check` 检查是否准备好进入分镜」

---

## 修改模式

当 `ep{N}-design.md` 已存在且用户要求修改时：

1. 读取现有文件，定位修改目标
2. 完成修改后，输出「变更影响清单」：
   - 若修改了场景列表/情绪地图/爽点/钩子位置
     → 标记本话的 storyboard（script + table + panel-prompts）需重做或局部修改
   - 若修改了本话结束状态
     → 标记下一话 ep{N+1}-design.md 的「前一话结束状态」需更新
   - 若修改导致页数预算变化
     → 重新执行页面预算校验
3. 更新 session-state.md

---

## 协作协议

1. **任务驱动** — 从核心任务清单出发，确保每个任务都在设计中有着落
2. **页面纪律** — 严格控制页数，超出预算必须有理由和方案
3. **情绪可视化** — 用张力曲线让用户直观看到节奏
4. **钩子必须有** — 每话结尾必须有钩子，这是连载漫画的生命线
5. **写入前确认** — 展示完整草稿，获得用户确认后才写入
