# 角色设计

逐角色引导设计，产出完整角色卡（内心引擎 + 外貌 + 视觉提示词）。
每个角色独立一个文件，同时维护角色索引和提示词汇总。

---

1. **必须存在**: `comic-project/concept/comic-concept.md`（角色速写）

## 角色设计流程（新角色）

### Step 1: 基础定位

- **名字**: 确认或取名
- **年龄/性别/职业**: 基础信息
- **叙事功能**: 主角 / 对手 / 导师 / 盟友 / 变节者 / 催化剂 / ...
- **一句话定位**: 这个角色在故事中的核心作用

---

### Step 2: 内心引擎

这是角色设计最核心的部分——驱动角色行动的内在逻辑。

- **欲望 (Want)**: 外在目标——角色自己说出来的「我想要什么」
- **需求 (Need)**: 内在成长方向——角色自己不知道的、真正需要的东西
- **谎言 (Lie)**: 角色相信的错误信念——阻碍他达到 Need 的东西
- **缺陷 (Flaw)**: 导致问题的性格特质
- **弧线方向**: 从 A（起点状态）到 B（终点状态）的变化

引导方式：
- 先问 Want（用户通常最清楚这个）
- 然后反推：「如果他的目标是 X，那什么内在弱点会阻碍他？」→ Flaw
- 再问：「他为什么有这个弱点？他相信什么错误的东西？」→ Lie
- 最后：「当他克服这个谎言时，他真正获得的是什么？」→ Need

---

### Step 3: 性格反应模式

用情境来定义性格（比抽象的「开朗、善良」有用得多）：

| 情境类型 | 反应方式 | 原因 |
|----------|---------|------|
| 面对危险 | ？ | 为什么这样反应 |
| 面对善意 | ？ | 为什么这样反应 |
| 面对背叛 | ？ | 为什么这样反应 |
| 情绪崩溃点 | ？ | 什么情况会突破底线 |

---

### Step 4: 语言画像

漫画中对白是角色最直接的表达，每个角色应有独特的「声音」。

- **语域**: 书面语 / 口语 / 混合
- **句式倾向**: 长句（思辨型）/ 短句（行动型）/ 碎片式（情绪型）
- **用语习惯**: 方言词汇、专业术语、年代感用语、外来语
- **口头禅/标志性句式**
- **典型台词示例**（3 句）:
  - 日常状态下的台词
  - 压力状态下的台词
  - 情绪爆发时的台词

---

### Step 5: 世界规则交互

- 这个角色和哪条世界规则有特殊关系？
- 这种关系如何影响角色的行动和命运？
- （如 worldbook.md 不存在，此步可跳过，标记为待补充）

### Step 7: 外貌与视觉设计

**标志性特征**（外貌以外的识别标记）:
- 习惯性动作
- 标志性物品

**外貌设计**:
- 整体描述（中文）
- 标志性表情 3 种：常态 / 战斗或紧张 / 脆弱或柔软
- 服装描述 + 变化时间线（第几话换装）

**视觉提示词**（适配 Nano Banana Pro）:

外貌锚定词生成规则：
- 以人物类型开头（1girl/1boy/character）
- 描述发型、发色
- 描述眼睛特征
- 描述服装
- 描述标志性特征
- 添加年龄/体型关键词
- 示例: `1girl, long silver hair, heterochromia eyes (blue and amber), tattered military jacket, mechanical left arm, slender, teenage`
  （一个女孩，银色长发，异色瞳（蓝色和琥珀色），破旧军用夹克，机械左臂，纤细，青少年）

表情变体词：
- 常态: `calm expression, slight smile, relaxed posture`
- 紧张: `intense gaze, clenched jaw, tense shoulders`
- 脆弱: `teary eyes, fragile smile, hunched shoulders`

---

### Step 8: 确认与输出

1. 展示完整角色卡草稿
2. 用 `AskUserQuestion` 确认
3. 写入文件：

   - 更新 `comic-project/prompts/character-prompts.md` — 提示词汇总
4. 更新 `production/session-state.md`

## 角色索引格式

`character-index.md`:

```markdown
# 角色索引

## 角色总表
| 角色名 | 故事功能 | 阵营/势力 | 首次登场话 | 设计状态 | 文件链接 |
|--------|---------|----------|-----------|---------|---------|

## 角色关系网络
| 角色A | 角色B | 关系 | 张力来源 | 可能发展 |
|--------|--------|------|---------|---------|
```

## 提示词汇总格式

`character-prompts.md`:

```markdown
# 角色提示词汇总

## {角色名}

### 外貌锚定词
- EN: {英文提示词}
- CN: {中文翻译}

### 表情变体
- 常态 EN: ... / CN: ...
- 紧张 EN: ... / CN: ...
- 脆弱 EN: ... / CN: ...

### 组合示例
{角色 + 场景 + 情绪的拼装示范}
```

## 修改模式

当某角色卡已存在且用户要求修改时：

1. 读取现有角色卡，定位修改目标
2. 完成修改后，输出「变更影响清单」：
   - 若修改了内心引擎/弧线方向
     → 标记 story-structure.md 的角色弧线追踪需更新
     → 标记该角色出场话的 ep{N}-design.md 需复查
   - 若修改了性格反应模式
     → 标记该角色出场话的 storyboard 中该角色行为需复查
   - 若修改了外貌/视觉提示词
     → 标记 character-prompts.md 需同步更新
     → 标记该角色出场话的 panel-prompts 需重新生成
   - 若修改了关系网络
     → 标记 character-index.md 的关系网络需同步更新
     → 标记相关角色的角色卡中「关系网络」需交叉更新
3. 同步更新 character-index.md 和 character-prompts.md
4. 更新 session-state.md

## 协作协议

1. **逐步引导** — 每个 Step 充分对话后再推进
2. **内在驱动优先** — 先设计内心引擎，再设计外貌
3. **情境定义性格** — 用具体情境而非抽象形容词
4. **提示词可调** — 视觉提示词是起点，用户可以根据出图效果调整
5. **写入前确认** — 展示完整角色卡，获得用户确认后才写入
