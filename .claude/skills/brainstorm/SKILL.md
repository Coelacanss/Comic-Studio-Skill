# 漫画概念孵化

从零开始，通过 6 个阶段的引导式对话，帮助用户把模糊灵感发展为完整的漫画企划书。

---

## 准备工作

1. **解析参数**: 检查是否有题材关键词（如 `末日冒险`、`赛博朋克`）。
   无参数则完全开放式探索。

2. **检查已有企划**:
   - 读取 `comic-project/concept/comic-concept.md`（如存在 → 进入续写/修改模式）
   - 如果存在，展示当前内容，询问是修改还是重新开始

3. **核心原则**:
   - 这是**协作式探索**，AI 是创意引导者，不是替代者
   - 在每个阶段充分对话后再推进，不要默默生成一切
   - 使用 `AskUserQuestion` 在关键决策点捕获用户选择
   - 不评判任何想法 —— 探索阶段没有坏主意

---

## Phase 1: 创意发现（了解创作者）

先了解人，再了解漫画。以对话方式（不是问卷）询问：

**情感锚点**:
- 有没有哪部漫画/动画/小说的某个场景让你印象特别深刻？是什么具体感觉打动了你？
- 你心目中「理想的漫画」给读者的是什么感受？

**口味画像**:
- 你最喜欢的 3 部漫画/动画是什么？它们有什么共同点？
- 有没有你明确不想碰的题材或风格？为什么？
- 你更喜欢：热血战斗 / 细腻情感 / 烧脑悬疑 / 日常治愈 / 史诗冒险？

**目标读者**:
- 你想画给谁看？（同龄人 / 青少年 / 全年龄 / 特定圈子）
- 你想在哪个平台发布？（微博 / 小红书 / 条漫平台 / 同人展 / 自印）

**实际约束**:
- 你打算做短篇（1-5话）、中篇（6-20话）还是长篇（20+话）？
- 每话大概多少页？（通常 24-32 页，条漫另计）
- 更新频率预期？

**综合**: 将回答整理为 **创意简报**（3-5 句话概括创作者的情感目标、口味画像和约束条件）。
读回给用户确认是否准确。

---

## Phase 2: 概念生成

基于创意简报，生成 **3 个截然不同的概念方向**。使用以下技法：

**技法 1: 核心冲突先行**
从主要矛盾出发（人 vs 人 / 人 vs 环境 / 人 vs 自我 / 人 vs 社会），
围绕这个矛盾构建故事。

**技法 2: 混搭法**
组合两个意想不到的元素：[类型A] + [主题B]。两者的张力产生独特看点。
例：「末日生存 + 美食」「校园日常 + 克苏鲁」「赛博朋克 + 中医」

**技法 3: 情感倒推法**
从你想让读者获得的核心情感出发（燃 / 泪目 / 毛骨悚然 / 温暖 / 震撼），
倒推需要什么样的角色和剧情来制造这种感受。

每个概念呈现：
- **暂定名称**
- **电梯演讲**（1-2 句核心卖点）
- **核心冲突**（一句话）
- **核心情感**（读者的主要情绪体验）
- **独特看点**（「像 X，但是 Y」）
- **类型/题材标签**
- **预估规模**（短/中/长）
- **为什么可能成功**（1 句）
- **最大风险**（1 句：最可能失败的原因）

展示三个概念，用 `AskUserQuestion` 让用户选择：
选一个深入、混合元素、或要求生成新概念。不施加选择压力。

---

## Phase 3: 概念深化

对选中的概念进行结构化深化：

**故事前提**:
- 用「如果……会怎样？」的句式重新表述
- 这个前提能产生多少话的故事？和预估规模是否匹配？

**主题探索**:
- 这个故事在探讨什么？（不是情节，是主题）
- 主题可以有多个层面吗？
- 主题和核心冲突的关系是什么？

**结局方向**:
- 胜利型（代价几何？）/ 悲剧型 / 开放型 / 苦乐参半型
- 结局和主题的关系：结局是对主题的什么回答？

**参考作品**:
- 调性参考（整体感觉像哪部作品）
- 风格参考（视觉/叙事节奏像哪部）
- 结构参考（剧情编排方式像哪部）
- 反面参考（绝对不要像哪部）

---

## Phase 4: 角色速写

**只做速写，不展开**（详细设计交给 `/design-character`）。

- 主角：名字 + 一句话定位 + 核心矛盾
- 对手/障碍：名字 + 一句话定位 + 和主角的关系
- 关键配角 2-3 人：名字 + 一句话定位
- 角色之间最关键的张力关系是什么？

---

## Phase 5: 世界观速写

**只做速写，不展开**（详细设计交给 `/design-world`）。

- 世界核心概念（一段话）
- 这个世界和现实世界最大的区别是什么？
- 这个区别如何制造故事的可能性？

---

## Phase 6: 确认与输出

1. 整合所有内容，展示完整企划书草稿
2. 用 `AskUserQuestion` 确认：满意 / 需要调整某部分 / 重来
3. 满意后写入 `comic-project/concept/comic-concept.md`

**`comic-concept.md` 包含的字段**:

```markdown
# {作品名称}（暂定）

## 基本信息
- 类型/题材标签
- 目标读者画像
- 预估规模（短篇/中篇/长篇）
- 单话目标页数

## 核心概念
- 电梯演讲（1-2句核心卖点）
- 核心冲突（一句话）
- 核心情感（读者应获得的主要情绪体验）
- 主题方向（故事想探讨什么）
- 故事前提（如果……会怎样）

## 角色速写
（每角色：名字 + 一句话定位，不展开）

## 世界观速写
（核心概念，不展开）

## 结局方向
- 类型 + 和主题的关系

## 参考作品
- 调性参考 / 风格参考 / 结构参考

## 风险评估
- 最大风险（最可能失败的原因）
```

4. 创建 `comic-project/production/session-state.md` 初始版本
5. 推荐下一步：
   - 「运行 `/design-world` 开始构建世界观」
   - 「运行 `/design-character` 开始设计角色（如果角色对你的故事更核心）」
   - 「运行 `/style-guide` 先确定视觉风格（如果你已经有很强的视觉想象）」

---

## 修改模式

当 `comic-concept.md` 已存在且用户要求修改时：

1. 读取现有文件，展示当前内容
2. 引导用户确认修改范围
3. 完成修改后，输出「变更影响清单」：
   - 列出所有读取 comic-concept.md 的下游文件
   - 逐条判断：本次修改是否影响该下游文件
   - 对受影响的文件标注「需要同步更新」
4. 更新 session-state.md

---

## 协作协议

1. **引导而非替代** — 提供框架和选项，让用户做创意决策
2. **充分对话** — 每个 Phase 都要和用户充分交流后再推进
3. **不评判** — 探索阶段所有想法都有价值
4. **用户节奏** — 用户可以在任何阶段停下来，下次继续
5. **写入前确认** — 展示完整草稿，获得用户确认后才写入文件
